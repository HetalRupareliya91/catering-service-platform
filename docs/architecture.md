# Architecture

```
backend/   Express API (models -> validators -> services -> routes)
frontend/  Customer website + mobile PWA (plain HTML/CSS/JS, no build step)
admin/     Admin panel (plain HTML/CSS/JS, no build step)
docs/      API and report documentation
```

## Request flow

1. `routes/index.js` mounts every `*.routes.js` under `/api`.
2. Module routes are generated by `lib/crud.js` from the model definition.
3. Input is checked by `lib/validate.js`, stored by `db.js` as JSON files.
4. Admin-only endpoints use signed HMAC tokens (`middleware/auth.js`).

## Self-describing UI

`GET /api/meta/entities` returns every model's fields and access rules.
The website and admin panel build navigation, tables and forms from it and
load optional per-module scripts and styles, so a new module appears in the
UI as soon as its backend model exists.

## Mobile

- Website: bottom navigation, single column cards, installable PWA with offline shell.
- Admin: off-canvas sidebar on tablets, tables collapse into cards on phones.
